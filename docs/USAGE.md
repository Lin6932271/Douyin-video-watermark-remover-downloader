# 拾影 1.2.0 使用说明

## Android

1. 安装本次交付的 `shiying-1.2.0.apk`（Android 10+）。包名不变，签名与仓库原 APK 一致。没有自动安装到用户手机。
2. 复制抖音分享内容，点击“粘贴” → “解析作品”。作品可以是视频、图集或实况。
3. 结果展示图片/动图、实况片段和视频数量。一张实况通常对应 2 个文件。
4. “保存全部素材到相册”保存整组；“选择素材保存…”可以只选动态片段或部分图片。
5. 图片/动图在 `Pictures/拾影/`；视频/实况动态片段在 `Movies/拾影/`。同一张实况的两个文件拥有相同作品 ID、时间戳和序号。
6. 动图保持服务器返回的 GIF/WebP/PNG 等原始格式，不强制转 JPG。系统相册不支持播放某种格式时，可在“最近保存”中分享到支持它的查看器。
7. 部分文件失败不会删除已成功文件；结果显示成功/失败数量及素材序号。取消也只清理正在写入的未完成条目。
8. 原有视频历史记录仍可打开，新图片记录使用正确 MIME 查看与分享。

## 实况不动怎么办

本版保存的是图片 + MP4 原始素材，**不是手机品牌专用实况容器**。可从“最近保存”打开 `live_video` 动态片段播放。仅点击图片不会使独立 MP4 自动与图片合成。

如果提示“实况未返回动态片段”，表示这次页面数据仅含静态图。可使用内置网页，完成验证后播放实况，再读取页面。不要把只保存静态图当成动态片段保存成功。

## 解析或下载失败

- 内置网页出现验证/登录时自行完成，再点“读取当前页面”。页面锁定作品 ID，避免误下载推荐内容。
- 地址过期后重新解析，不直接反复点旧下载地址。
- HTTP 403、区域/会话限制或接口变化可能使某一资源不可访问；有备用地址时自动切换。
- 返回 HTML 验证页或错误媒体类型时不会以 `.mp4`/`.jpg` 冒充成功。
- 安装出现签名冲突时，先保留原应用和数据并核对安装包，不自动卸载旧版。

## iOS

只交付源码，需要 Mac/Xcode 编译和自己的 Apple 签名。操作为粘贴 → 解析作品 → 下载全部素材 → 在记录中“存入相册”或“分享”。本版保持前台下载。原始动图格式若不被系统 Photos 接受，可用分享保存到文件。

实况同样保存为图片 + MP4，不声称支持原生 Live Photo。没有进行 iOS 编译或手机端验证，详见 `ios/README.md`。

## 反馈时提供

手机型号与 Android/iOS 版本、Android WebView 版本、分享链接、完整错误和失败序号。不要提供 Cookie、API Key 或登录令牌。
